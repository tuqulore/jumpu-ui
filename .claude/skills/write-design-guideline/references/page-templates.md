# ページ型別テンプレート

`packages/docs` のページは 5 型ある。型ごとに骨格を決めておき、ページごとに構成を考え直さない。

## Principles

価値観を書く。判断が割れたときの決着点になる粒度で書き、手順は書かない。

```markdown
# 見出し（扱う対象を指す句）

（原則を 1 文で述べる）

なぜなら、**（根拠）**からです。

（原則が効かない範囲、または適用しない場合があるなら、その境界を書く）
```

各原則には根拠を添える。根拠のない原則は、読者が例外を判断できないため守られない。

## Tokens

尺度、または役割に名前を与えたものを書く。**尺度と配布状況を必ず区別する**。

```markdown
# Spacing

（この尺度が何を規格化しているかを 1 〜 2 文で）

## 尺度

| 名前                 | 値       | 参照方法                  |
| :------------------- | :------- | :------------------------ |
| `--spacing-relative` | `0.25em` | `var(--spacing-relative)` |

（配布していないものは「参照方法」を「なし（component CSS に直接記述）」と書く）

## 使い方

（どの尺度をいつ選ぶか。判断基準を書く）

## コンポーネントでの使われ方

（実装が実際にどう使っているか。読者が挙動を予測できるようにする）
```

「使い方」の節がガイドラインにあたる。独立したページを作らず、尺度と同じページに置く。

## Components

**用途を先に、リファレンスを後に**置く。

```markdown
# Button

（何を表すコンポーネントかを 1 〜 2 文で）

## いつ使うか

（この部品を選ぶ場面。選ばない場面も書く）

## OutlinedButton / TextButton との使い分け

（近いコンポーネントがあるときだけ置く）

## 例

### 基本

### リンクとして使う

### フォームの送信に使う

## ユーティリティによる調整

| 調整したいこと | 書き方         |
| :------------- | :------------- |
| 文字を小さく   | `text-xs`      |
| 全幅に         | `w-full block` |

## マークアップ規約

| 位置   | 要素 / 属性                        | 要否 |
| :----- | :--------------------------------- | :--- |
| ルート | `button` / `a` / `[role="button"]` | 必須 |
| ルート | `[disabled]`                       | 任意 |

## 状態

（どの属性でどの状態が発火するか。効かない組み合わせも書く）

## アクセシビリティ

（準拠する APG パターン名。逸脱する場合はその理由。利用側が実装する必要のあること）
```

**例の見出しは用途名にする**。`## Small` `## Rounded` `## Anchor` のようなバリアント名の列挙は作らない。読者に「Small という変種がある」と読ませてしまい、原則「コンポーネントにバリアントを持たせない」と矛盾する。サイズや角丸の調整は「ユーティリティによる調整」の表に入れる。

`## 例` の各項目は `:::raw` の描画と、直後の同じマークアップのコードブロックで構成する。

## Recipes

場面に対する組み合わせ方を書く。ページ名はコンポーネント名ではなく**場面名**にする。

```markdown
# ログイン

（この場面で何を達成させるかを 1 〜 2 文で）

## 設計の指針

（この場面で守るべきこと。エラーの伝え方、入力の並べ方など）

## 例

### 入力前

### 入力に誤りがあるとき
```

状態（空、誤りあり、送信中）は場面の一部なので、ここで扱う。

## Content

コンポーネントに入る中身の作り方を書く。文言、画像、動画、アイコン。

```markdown
# アイコン

（何を定めるページかを 1 文で。指定しないなら「指定しない」と書く）

## 選び方

（判断基準）

## 現状

（実装が特定のものに依存しているなら、その事実と今後の方針）
```
